# Подготовка GitHub Release 1.3.0

Публикация не выполняется этим документом. Установщик настроен на tag
`v1.3.0`, пакетную версию `1.3.0-r1` и базовый URL:

`https://github.com/quargelk/easy-vless/releases/download/v1.3.0`

## Подготовить assets

Сборки уже лежат в `dist/sing-box-lx-integration/`; повторная сборка не нужна.
Проверить их суммы и собрать плоскую папку assets:

```sh
for f in dist/sing-box-lx-integration/*/SHA256SUMS; do
  (cd "${f%/*}" && sha256sum -c SHA256SUMS) || exit 1
done
sh scripts/prepare-release-assets.sh
cd dist/release-assets-1.3.0-r1
sha256sum -c SHA256SUMS
```

Скрипт сверяет локальные четыре манифеста, проверяет совпадение одноимённых
пакетов, объединяет одинаковые architecture-independent assets, добавляет
четыре ABI-пакета sing-box-lx и `install.sh`, затем формирует один общий
`SHA256SUMS`. Результат — 15 загружаемых файлов плюс сам манифест. Все имена
совместимы с `pkg_file()` в installer. Этот манифест обеспечивает целостность,
но для IPK не является криптографической подписью релиза.

GitHub Release assets загрузить плоским списком файлов из этой директории.
Не загружать четыре исходных `SHA256SUMS`: их заменяет общий манифест.
Черновик выпуска можно подготовить отдельно, но `gh release create`, push tag
и публикацию выполнять только после отдельного разрешения.

## Блокер доверия APK

APK из имеющихся комплектов проверены командой SDK `apk verify` и показывают
`UNTRUSTED signature`. Это значит, что подпись пакета присутствует, но её ключ
не доверен чистой системе OpenWrt. Установщик правильно вызывает `apk verify`
и откажется ставить такие файлы, пока публичный ключ подписи не установлен
в доверенное хранилище роутера. В исходниках/комплектах нет ключа для выпуска.

До публикации или установки APK-выпуска необходимо выбрать доверенную схему:

1. Уполномоченный владелец выпуска подписывает все APK официальным ключом
   проекта, передаёт только публичный ключ и fingerprint отдельным доверенным
   каналом и документирует предварительное добавление ключа в OpenWrt.
2. Пересчитать общий `SHA256SUMS` после подписи и заново проверить подпись
   каждого APK как доверенную тестовым ключом/чистым тестовым rootfs.
3. Убедиться, что `--check` и реальная установка после предварительной
   установки публичного ключа проходят на OpenWrt 25.12.

Не публиковать приватный ключ и не включать `--allow-unsigned` для удалённого
GitHub Release. До выполнения этих шагов APK-ассеты подготовлены, но выпуск
нельзя считать готовым к безопасной установке на чистый роутер.

## Проверка установщика

Скачать скрипт с release URL. `--check` выполняет проверки устройства, HTTPS,
фидов, зависимостей, размера и release assets, скачивая их только во временный
каталог; установки и изменения системы не выполняет:

```sh
wget -O /tmp/easy-vless-install.sh \
  https://github.com/quargelk/easy-vless/releases/download/v1.3.0/install.sh
sh /tmp/easy-vless-install.sh --check
```

Для доверенного HTTPS mirror, где доступны те же имена assets и общий
`SHA256SUMS`, применить:

```sh
sh /tmp/easy-vless-install.sh --check --base-url https://mirror.example/releases/v1.3.0
```

`--base-url` принимает только HTTPS и отключает автоматические сторонние
зеркала. После публикации провести проверку release URL и зеркала в OpenWrt
rootfs 24.10/IPK и 25.12/APK; обычный Linux-хост не является заменой `--check`
на OpenWrt. Не запускать установку на физическом TR3000 в рамках подготовки
релиза.

## Release notes

В описании выпуска указать Easy VLESS `1.3.0-r1`, sing-box-lx `1.14.4-lx.35`,
поддерживаемые проверенные комплекты `x86_64` и `aarch64_cortex-a53`, версии
OpenWrt 24.10/IPK и 25.12/APK, ограничения ABI и необходимость ключа APK.
Контрольные суммы сверять с загруженными assets перед публикацией. Не заявлять
проверку LAN DNS/DHCP или маршрутизации на TR3000: live trial не проведён.
