# Интеграция sing-box-lx

Easy VLESS 1.3.0-r1 использует стабильный sing-box-lx **1.14.4-lx.35**.
Сборка закреплена на коммите `f1bac271853eaf13398ce1030c948aebc3aed2e1`,
Go 1.26.10 и версиях подмодулей этого коммита.
[Релиз и исходный код](https://github.com/Leadaxe/sing-box-lx/releases/tag/v1.14.4-lx.35)

## Пакеты и выбор ядра

`easy-vless` содержит runtime, `easy-vless-sing-box` устанавливает
генератор и клиент Clash API и зависит от `sing-box-lx`.
Ядро владеет `/usr/bin/sing-box-lx` и зависит от `ca-bundle`.
Установленный `sing-box` или `sing-box-tiny` продолжает владеть
`/usr/bin/sing-box`. У пакетов разные имена и пути, виртуальный
пакет sing-box прежнему владельцу предоставляет его собственный пакет.
Xray по-прежнему использует опциональные `easy-vless-xray` и `xray-core`.

UCI сохраняет идентификатор `type=sing-box`, значения узлов,
подписок, маршрутизации и DNS. Пустой `global_app.sing_box_file`
и прежнее значение `/usr/bin/sing-box` разрешаются в новый
пакетный путь. Остальные явные пути проверяются на совместимость.
Runtime читает `version` с таймаутом и ожидает стабильную версию
LX с тегами `with_utls` и `with_clash_api`. Для официального комплекта
установщик проверяет точную версию поставленного исполняемого файла.

## Конфигурация и процесс

`app_acl.lua` разрешает выбранный узел и правила UCI.
`util_sing-box.lua` формирует конфигурацию с typed DNS, FakeIP,
правилами маршрутизации, TCP/UDP-inbound и URL Test. Runtime прогоняет
`sing-box-lx check` перед запуском. Файлы JSON, логи проверки и снимок
применённого UCI создаются под `umask 077`. RPC возвращает безопасный
статус ошибки и путь к подробностям для администратора.

Службой управляет существующий `/etc/init.d/easy_vless`. При перезапуске
некорректная конфигурация отклоняется до остановки текущего экземпляра.
После запуска основной и временный тестовый экземпляры проверяются
по PID, аргументу конфигурации и владельцу TCP listener в `/proc`.
Таймаут ожидания составляет 25 секунд. При отказе основного ядра
запуск прерывается и runtime удаляет свои временные изменения. Если
до перезапуска работал прокси и есть снимок применённого UCI, служба
пробует восстановить этот снимок, сохранив отклонённый в tmpfs.
На перезагрузке временные снимки сбрасываются.

## Возможности

| Функция | Реализация и проверка |
| --- | --- |
| VLESS TCP, TLS, Vision, WS, gRPC, HTTPUpgrade | Генератор Easy VLESS. Локальные HTTPS-сессии через реальное ядро. |
| VLESS REALITY и uTLS | Тег `with_utls`, UCI public key и short ID. Локальная сессия REALITY/Vision с временными ключами прошла. |
| Trojan TLS | Генератор и локальная HTTPS-сессия. |
| Clash API и URL Test | `with_clash_api`, loopback с секретом. Существующие методы групп остаются доступны. |
| QUIC и DNS | `with_quic` сохраняет DoQ и HTTP/3. Генератор сохраняет обычный DNS и FakeIP. |
| TPROXY, REDIRECT, IPv6 | Существующие inbounds, policy routing и таблица `inet easy_vless`. Приём JSON и маршрутизация LAN проверяются независимо. |
| XHTTP | Backend принимает `host`, `path`, `mode`. Допустимы `auto`, `packet-up`, `stream-up`, `stream-one`. Проверены загрузка конфигураций и HTTPS через Xray 26.11.9 в трёх явных режимах XHTTP/TLS. |
| mKCP и Xray XHTTP extra | Явно требуют узел Xray. Неподдерживаемые параметры отклоняются. |

URL-импорт воспринимает `splithttp` как XHTTP. Базовые параметры
поддержаны в подписках sing-box JSON. Объекты XHTTP с расширенными
полями и Xray `extra` требуют отдельного преобразования схемы.
Тесты XHTTP пройдены на loopback с TLS. XHTTP с REALITY и промежуточным
HTTP-сервером требуют отдельных сетевых проверок.
[Схема XHTTP версии 1.14.4-lx.35](https://github.com/Leadaxe/sing-box-lx/blob/v1.14.4-lx.35/option/v2ray_xhttp.go)

У sing-box-lx хеш публичного ключа TLS имеет другую семантику,
чем Xray `pinnedPeerCertSha256`. При старом отпечатке сертификата
генератор просит использовать Xray или явно доверенный сертификат TLS.
Наличие отпечатка больше не переводит проверку TLS в insecure.
