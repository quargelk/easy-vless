# Backend для следующего этапа LuCI

Меню задаётся в `luci/root/usr/share/luci/menu.d/luci-app-easy-vless.json`.
Представления находятся в `view/easy_vless/`, общие RPC-запросы
и компоненты в `easy_vless/common.js`, проверка синтаксиса правил
в `easy_vless/rulecheck.js`. Русский каталог собирается через
`scripts/po2lmo.py`. Английский используется в исходных msgid.

## Карта представлений

| Представление | Основные обязанности | Точки интеграции |
| --- | --- | --- |
| Main | Выбранный узел, включение, состояние, журнал, быстрый тест | UCI, `status`, `check`, `start`, `stop`, тесты |
| Node List | Редактор VLESS/Trojan, импорт, подписки, группы, сортировка и задержка | UCI, `import`, `nodes`, `subscribe`, `test`, `urltest_node`, `groups`, `group_test` |
| Rule Manage | Наборы правил, цели, ресурсы, объяснение маршрута | UCI, `resources`, `diag/explain` |
| Diagnostics | DNS, прокси, маршрут, перехват и политика | `status`, `diag`, тесты |
| Settings | DNS, DHCP-интеграция и параметры перенаправления | UCI, перезапуск через `start` |
| Maintenance | Резервные копии, импорт/экспорт и обновление | `transfer`, `update` |
| Setup Wizard | Первоначальная настройка и проверка условий | `wizard_state`, `wizard`, `status`, UCI |

## RPC

Объект `luci.easy_vless` реализован через rpcd exec. Список методов
возвращает `luci.easy_vless list`, вызов идёт через `ubus call luci.easy_vless METHOD JSON`.
Существующие клиенты читают поля `code`, `ok`, `output` и
дополнительные поля конкретного метода. Их значения сохранены.

| Метод | Вход | Ответ, ошибки и побочные эффекты |
| --- | --- | --- |
| `status` | `{log_from?: number}` | Состояние службы, ядра, системы, журнал, `log_lines`, `subscribe_busy`. |
| `check` | `{node?: string}` | `{code,ok,node,output,error_kind?}`. При пустом node проверяет выбранный узел. Не включает перехват. |
| `start` | `{}` | `{code,ok,node,output,log_mark,accepted?,error_kind?}`. Проверяет, затем планирует старт или перезапуск. `accepted` означает постановку действия. |
| `stop` | `{}` | `{code,ok,log_mark,...}`. Сохраняет флаг отключения и планирует остановку. |
| `import` | `{links: string}` | Результат импорта ссылок, количество узлов и ошибка при отклонении. |
| `nodes` | `{action,id?,key?}` | `delete`, `delete_all_plan`, `delete_all`, `restore`. Возвращает `ok`, код `error` и данные операции. |
| `subscribe` | `{action,id?}` | `update`, `state`, `truncate`. `state.results` содержит JSON-строку на идентификатор, `busy` показывает текущую задачу. |
| `test` | `{action,kind?,nodes?}` | `state`, `add`, `cancel`, `clear`. `kind` равен `server` или `url`. `nodes` содержит пробелы между ID. |
| `urltest_node` | `{node,url?}` | `ok`, `delay` в мс, HTTP-код или `error_kind` и сообщение. Отдельный loopback SOCKS5. |
| `groups` / `group_test` | `{}` / `{group}` | Состояние группы и результаты Clash API либо диагностическая ошибка. |
| `resources` | `{}` | Подготовленные наборы доменов и шаблоны правил. |
| `diag` | `{action,arg?}` | `explain`, `dns`, `forwarding`, `connection`. Для `explain` аргумент содержит JSON-строку. |
| `wizard_state` / `wizard` | `{}` / `{action}` | Текущее состояние мастера, `backup`, `restore`, `finish`, `connectivity`. |
| `transfer` | `{action,data?,kind?}` | Экспорт, проверка импорта, применение и восстановление. Формат зависит от действия. |
| `update` | `{action,tag?}` | `check`, `recheck`, `state`, `install`. Длительная установка возвращает `{ok,started}`, затем опрашивается `state`. |

Источники истины для полей и действий содержатся в
[диспетчере RPC](../luci/root/usr/libexec/rpcd/luci.easy_vless) и
[клиентских объявлениях](../luci/htdocs/luci-static/resources/easy_vless/common.js).
Служебные Lua-модули описаны в [технической документации](technical.md).

### Состояние службы и ядра

`status.api_version` равен 1. `state` принимает `stopped`,
`applying`, `running` или `error`. `enabled` представляет настройку
UCI, `running` наличие процесса с ожидаемой конфигурацией, `busy`
блокировку запуска, остановки или перезапуска. `last_error` пуст либо
содержит `start_failed`, `apply_rolled_back` или `rollback_failed`.
PID проверяется по аргументу конфигурации. Базовый статус не делает
сетевой запрос и не подтверждает доступность прокси.

`core` содержит `name`, `version`, `installed`, `compatible`,
`tags`. Старые `singbox_bin`, `singbox_version`,
`singbox_backend` и `singbox_min_version` остаются для текущего UI.
`system` содержит релиз OpenWrt, ABI, доступную RAM и overlay в КиБ,
доступность fw4 и поддержки nftset у dnsmasq. Отсутствующее измерение
не входит в JSON. Ошибка проверки, доступность upstream и расширенная
диагностика запрашиваются отдельными методами.

После `start` или `stop` опрашивайте `status` с `log_from` равным
`log_mark`. Быстрый ответ RPC не является результатом сетевого
применения. Методы обновления возвращают `phase`, `status`,
`message`, время и признак `busy`. Тестовая очередь имеет свой
цикл опроса и поддерживает отмену ожидающих тестов.

## UCI и права

В `/etc/config/easy_vless` глобальный узел и DNS задаёт `global`,
перехват задаёт `global_forwarding`, подписки описываются секциями
`subscribe_list` и `global_subscribe`. Серверы, шунты и группы
URL Test хранятся в `nodes`; правила в `shunt_rules`, локальные
правила доступа в `acl_rule`. Идентификаторы секций стабильны
при сохранении и переиспользуются как ссылки. Подробности параметров
в [шаблоне UCI](../files/0_default_config) и
[технической документации](technical.md).

Добавление, редактирование и выбор узла или подписки выполняются
через существующие LuCI UCI формы. Структурные операции и массовый
импорт проходят через rpcd. Взаимоисключающие операции службы и
теста используют flock. Импорт и обновление подписок имеют отдельную
блокировку. Отмена уже работающего обновления подписки пока отсутствует.

ACL `luci-app-easy-vless` различает диагностические и изменяющие
методы. UCI-доступ в существующей ACL охватывает всю конфигурацию
Easy VLESS, включая адреса подписок и учётные данные узлов.
При выдаче ограниченного диагностического доступа нужен отдельный
ACL и редактированный список узлов. Конфигурации ядра и временные
резервные копии должны оставаться закрытыми для обычных пользователей.
Сырые логи ядра и json-конфигурации не следует добавлять к общему статусу.

## Работа над следующим интерфейсом

1. Перевести представления статуса на `api_version`, `core`, `system`
   и состояния службы. Сохранить работу со стабильными ID.
2. Выделить операции проверок, подписок и обновлений в единый клиентский
   слой с предсказуемым опросом и отображением ошибок.
3. Сохранить текущие UCI-поля при изменении компонентов формы. Для
   доступа без права на секреты добавить узкоспециализированные
   методы списка узлов и подписок.
4. Подключать редактирование XHTTP после проверки трафика и определения
   параметров совместимости. Для неподдерживаемых полей показывать
   ошибки на уровне проверки.
5. После изменений прогнать Wizard, диагностику, сохранение UCI,
   импорт, резервное копирование, обновление и проверку сессий ACL
   в браузере.
